Quantum networks distribute entanglement among nodes connected by quantum channels. Many established protocols treat Bell pairs, entangled states of two qubits, as their basic resource~\cite{buckley2024bellkat,buckley2025pbkat}. Other proposals use multipartite entanglement as an intermediate resource: all-photonic repeaters, for example, prepare graph states and combine them through measurements and fusions to distribute entanglement without long-lived quantum memories~\cite{azuma2015_all-photonic,fischer2020distributinggraph}. A protocol specification must account for the states present at different nodes, the operations that consume and produce them, and the possibility that an operation fails.

Graph states offer a compact description of a useful family of stabilizer states: vertices denote qubits and edges specify the controlled-Z gates used to prepare the state~\cite{vandennest2004graphical}. A literal graph description, however, records details that a distribution protocol need not distinguish. Local complementations relate graph states through single-qubit Clifford operations, and the labels of qubits held at the same node can be exchanged. We therefore describe a resource by an equivalence class under local complementations and within-node qubit permutations. This abstraction keeps track of which nodes hold a multipartite state while hiding local corrections and memory labels.

The abstraction raises a semantic issue. A physical operation need not give the same output class for every representative of an input class: the fusion example in \cref{fig:LC-input-nonLC-output} produces distinct outcomes from locally equivalent inputs. We address this at the level of protocol specification by making the intended output class of each action explicit. Following PBKAT~\cite{buckley2025pbkat}, protocols combine actions sequentially across rounds and in parallel or with priority within a round, with guards and iteration expressing control flow.
